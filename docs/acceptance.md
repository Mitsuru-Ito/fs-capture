# 実OSVから歩ける空間への受入条件

更新: 2026-09-25。必要な証拠は受入目標であり、現状欄とは区別する。詳細は[実素材検証](real-capture-check.md)と[Phase A](phase-a-verification.md)を参照。

| 段階 | 必要な証拠 | 現状 |
| --- | --- | --- |
| 入力・抽出 | 元OSV、撮影モード、両魚眼の同期、抽出画像、区間の対応 | 実OSVのFFmpeg抽出成功。Macのネイティブ動画抽出は非対応。全素材への一般化は未確認 |
| マスク | 人物・移動物体の除去、静物の欠損、魚眼外周、白黒の意味 | 5位置に図形マスクを適用・目視。粗い矩形により背景も除外。SAM追跡の実素材品質は未確認 |
| SfM | 経路の連続性、登録された時刻と欠落区間、分断・折れ・二重化 | 5位置10/10画像が1モデルに登録。実寸・移動経路の正確さは未確認 |
| 3DGS | 実GPU最終反復のログ、最終PLY、別位置からのGaussian描画 | 10,000反復・199,931 Gaussianの生成と表示に成功。撮影地点・横移動後とも画質不合格 |
| 縮尺・座標 | 既知距離の校正・別距離の検証、共通変換、上下方向・開始位置 | SfM座標で保存。実寸校正と納品用座標調整は未実装 |
| 歩行 | 床抜け・壁抜け・出入口閉塞なし、ホームへ戻る、WASD以外の操作 | 衝突判定・歩行可能範囲は未実装。移動の受入試験はNOT_TESTED |
| 性能 | 基準PCを明記、1080pで30fps以上、読み込み時間とメモリ | 標準条件での受入計測はNOT_TESTED。ブラウザの瞬間fpsを合格根拠にしない |

## 判定を混同しない

処理成功は必要な成果物を生成し形式検査を通過したこと、閲覧品質合格は指定視点で用途に必要な情報を確認したこと、移動範囲合格は指定経路の画質・形状・操作を確認したこと、納品承認は顧客の用途・端末・公開範囲・提供条件を確認したことを指す。

現行CLIの`succeeded`は処理成功、`review`は各段階の人手確認であり、納品承認ではない。用途別QA・納品承認の専用データモデルはまだない。未確認の項目を合格に読み替えない。doctorの`PASSED`も個別項目の`scope`内の判定であり、`NOT_TESTED`は未実施、`UNKNOWN`は判定不能を表す。撮影点へのジャンプに変えても、表示品質の確認は必要。

## 三つの主要な失敗要因

1. **カメラモデル・同期の誤り。** 見た目の一部が合っても経路が折れる可能性がある。元動画の両レンズとSfM経路を比較し、必要に応じ校正・rig設定を調整。OSV直接入力と正距円筒図法の代替経路は別ジョブで比較する。
2. **撮影経路の観測不足と動く物体。** 登録画像率だけでは通路の欠落を隠せる。区間別に登録状態を確認し、視差不足の箇所を横にずらして再撮影。マスク有無の比較を記録する。
3. **見た目と衝突形状の不一致。** きれいなPLYでも歩行可能とは限らない。床・壁・出入口の衝突形状を重ねて確認し、自動生成と手補修の前後で同じ経路を歩く。失敗箇所を記録する。

## 公開用パッケージの設計方針（未実装）

`scene.json`にschema version、単位、軸、column-majorの`worldFromReconstruction`、開始位置、表示と衝突形状への相対参照を持たせる。変換は一度だけ適用し、カメラ・注釈・移動先にも同じ座標の規則を適用する。

`visual/`、`geometry/`、`navigation/`、`cameras.json`、`source-index.json`、`qa.json`を共通パッケージにまとめる。元OSVと正本PLYは別管理。未校正の座標をメートルとして扱わない。変換や入力が変わったら品質判定を無効化する。

ブラウザへの初期配布は静的な閲覧データのみとし、生成・削除などの管理機能を分離する。銘板等は別の高解像度画像で確認。人物、掲示物、業務情報の公開範囲を確認し、顔や文字が読めなくなったことだけで匿名化を保証しない。
