# 実素材検証: 2026-09-24〜25

## 確認できたこと

Apple M3 Max（GPU 40コア、ユニファイドメモリ128GB）、Spirula v2026.9.20、FFmpeg 8.1.2で検証した。動画・抽出画像・復元データはローカルの`work/`に保存し、Gitには含めない。

1. オリジナルOSVの2映像トラックはともに3840×3840・25fps・HEVCだった。サムネイル用のMJPEGトラックは動画から除外した。
2. SpirulaのGPU検出は成功した。サンドボックス内ではMetalへアクセスできず、制限外での実行が必要だった。
3. ネイティブ動画抽出は`VK_KHR_video_queue / VK_KHR_video_decode_queue`未対応で失敗した。失敗ログを保持した。
4. FFmpegを抽出に用いた経路では、10.28秒のOSVから8フレーム間隔で33時刻・66枚を抽出した。レンズごとのフレーム番号が一致し、元フレーム番号へ対応付けた。回転・スティッチ・投影変換は行っていない。
5. 各動画の複数時刻を目視すると、人物は動くが背景の視差は乏しかった。単独動画を移動撮影として扱う品質判定は承認していない。

## 別試行: 5つの位置からのSfM診断

同一空間に見える5本のOSVから各先頭フレーム・両魚眼を取り出し、診断用に1920×1920へ縮小。画像を`capture_00/cam0`から`capture_04/cam1`まで別フォルダに配置した。

設定は`sfm auto`、`--data-type individual --quality high --camera-model opencv-fisheye --pairs exhaustive --no-masks`。各動画の両レンズに個別の`dual-fisheye`リグを指定した。各動画の同じフレーム番号を、動画をまたいで同じ時刻・同じ撮影位置とは扱っていない。

| 指標 | 実測 |
| --- | ---: |
| 登録画像 | 10 / 10 |
| 出力モデル | 1 |
| 疎な3D点 | 4,148 |
| 再投影誤差・平均 | 0.374 px |
| 再投影誤差・中央値 | 0.279 px |
| 観測数 | 10,772 |
| ツールが報告した合計処理時間 | 3.350秒 |

**主張できるのは、5位置をまとめる経路で位置推定が成立したことまで。** この診断時点では元動画の撮影条件を確認中だった。後にユーザーから「ほぼ固定」と確認された。人物は未マスクで、実測寸法との比較もない。再投影誤差の小ささは、幾何形状の正確さや歩行可能性の保証ではない。出力された疎な点群を3DGS生成成功とは扱わない。

## 初回診断時点の次の検証

- 5位置の撮影条件を確認し、複数動画を1つのジョブにまとめる入力経路へ拡張。
- 人物・動く物体・魚眼外周を除外し、マスクあり／なしのSfMを比較。カメラ配置と観測範囲を目視・既知距離で確認。
- 位置推定の品質確認後、実GPUで3DGS学習を実行。Gaussianとして描画し、撮影位置からずらした視点で確認。
- 観測不足がある場合は移動撮影を追加。5位置から得た画像を時間方向に増やすだけでは、静的背景の新しい視差は得られない。
- 画質を確認してから、SOG・衝突形状・ブラウザ歩行へ進む。

初回診断時点のCLI自動テスト18件はローカルで成功。うち1件は合成した2トラック動画を実FFmpegで抽出し、元フレーム番号と画像枚数を確認する統合試験である。これらを3DGS・歩行の受入試験とは区別する。

## 追加試験: ほぼ固定の5位置から実GPU学習（2026-09-25）

ユーザーの依頼に基づき、同じ5本の各先頭フレーム・両魚眼10枚で試験した。Spirulaの図形マスクで魚眼外周・下端・人物付近を除外し、マスク画像を目視した。人物マスクは矩形による粗い指定で、背景も除外している。完全な人物除去の保証はない。

マスクありSfMは10/10画像を1モデルへ登録し、2,781点、再投影誤差は平均0.319px・中央値0.249pxとなった。未マスク診断とは別の復元を学習に使用した。

| 学習条件・結果 | 実測／設定 |
| --- | --- |
| 実行環境 | 上記M3 Max・Spirula v2026.9.20 |
| プリセット | 360-camera |
| 入力 | 1920×1920の魚眼10枚、学習時は解像度をさらに2分の1 |
| 投影 | 魚眼を維持、ピンホールへの変換なし |
| 座標 | train-frame=points、scene-center=none、縮尺未校正 |
| 短い試験 | 2,000反復、61.744秒、書出し5,422 Gaussian |
| 追加試験 | 10,000反復、254.396秒、上限200,000 Gaussian |
| 最終PLY | 199,931 Gaussian、属性・サイズ・有限値検査に合格 |
| PLY SHA-256 | 7996bf25542eb0db1c98e9f53602d4fdc205068c2a28cc959557ad9fe0bf7556 |

Spirula付属のWebビューアをローカルで起動し、Gaussianの大きさ・回転・不透明度を扱う描画で確認した。撮影カメラへ戻る選択欄と、左右へ0.1単位ずらす操作を検証用に追加した。距離の単位は未校正でありメートルではない。3DGS／3DGUTの描画モードを比較し、プレビューは3DGUTを初期値にした。学習設定のprimitiveは3dgsであり、描画方式の差による影響も残る。

**判定: 生成・ブラウザ表示の処理経路は成立。歩行用途の画質は不合格。** 10,000反復では建物や屋上の配置を識別できるが、手すり・床・遮蔽部分ににじみ、引き伸ばし、浮遊物が残った。撮影地点と横移動後の両方で問題が見られ、地点による品質差も大きい。5位置という疎な観測、粗いマスク、学習条件、投影方式の寄与はまだ切り分けていない。全画像を学習に使っており、未学習視点の正解画像との比較はしていない。ログ中のPSNRは汎化性能の評価値として報告しない。

成果物と設定・ログ・品質記録はローカルの `work/fixed-test-01/`、入力との対応は `work/five-position-diagnostic/inputs.json` に保存。単一動画CLIとは別の診断であり、複数OSVの自動ジョブ化はまだ実装していない。衝突形状、床、歩行可能範囲、SOG、FieldSplat接続は本試験の対象外。

検証を行ったPCで再表示する場合は、リポジトリ直下から以下を実行する。`work/`内のモデル・検証用ビューアはGit管理対象外であり、新しくcloneした環境には含まれない。

```sh
python3 -m http.server 8766 --bind 127.0.0.1 --directory work/fixed-test-01
```

URL: `http://127.0.0.1:8766/viewer/?model=../training-10000/step-000010000.ckpt/splat.ply`

次は既存素材でマスク・投影条件の比較を行い、画質の限界を切り分ける。歩行品質の検証には、その後、位置を連続的に変えた撮影を比較対象に加える。

## 第2回レビュー後: 複数素材の標準CLIによる再現

init-manifestから固定5素材を新規ジョブとして処理し、抽出・取り込みマスク・SfM・10,000反復の学習を完了した。抽出画像10枚とSfMの3バイナリは手作業版とハッシュ一致。新しい最終PLYは199,952 Gaussian。内部HTMLの画像・マスク・登録状態をブラウザ確認した。詳細・学習条件の差は[第2回レビュー対応](review-2.md)を参照。

これにより、以前の「複数OSVは手動診断のみ」という制約を標準CLIで解消した。ただし、新モデルの3D表示と画質評価はNOT_TESTEDであり、過去の画質不合格が改善した証拠とはしない。顧客納品は未成立。
